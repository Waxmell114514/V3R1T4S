# 提案 0003：分布式分片与 B′ 级（2026-11-25T05:09Z）

人已同意方向（"抽查分片，标 B′ 级"），本提案写出具体规则，等人确认后才作为正式规则用于里程碑。

## 问题
大 N 的 UpTo N 需要几十核·天。分片在多个云端会话里各自编译时，每个会话只能编译自己的分片模块；
编译产物不在同一环境，所以组合定理 `upTo_K`（导入所有分片模块）不会在任何一个环境里被完整编译。
这偏离 CONSTRAINTS 第 11 条"成果必须是 lake build 通过的 Lean 定理"。

## B′ 级的定义（提议）
一个 UpTo N 结果为 B′ 级，当且仅当：
1. 可靠性定理（如 checkWord_sound：∀ s < m, checkWord N s m = true → UpTo N）在主环境中为 A 级并经审计；
2. 每个分片 s < m 都有一份运行记录：执行环境（会话 ID）、提交哈希、分片源文件 sha256、Lean 版本、
   `lake build <分片模块>` 的退出码与输出末尾、墙钟时间；全部分片的记录存于 certs/<id>/；
3. 独立审计员在另一环境从头（删除 ETNative 与分片编译产物）重编至少 max(2, 5%) 个随机分片，全部通过；
4. 组合定理在主环境中以"分片定理为前提"的形式编译通过（例如证明 (∀ s < m, checkWord N s m = true) → UpTo N 的具体实例），
   即所有 Lean 侧推理在一个环境中检查，只有分片的布尔求值分布在多处。
B′ 级额外信任：各会话的 Lean 工具链与预编译库、各会话如实报告运行结果（由抽查部分验证）。

## 不变
B′ 不得写成 B 或 A；里程碑 M2 若以 B′ 达成，报告必须写明 B′ 及抽查比例。
