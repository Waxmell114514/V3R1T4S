## 1. 定理陈述与验证范围（KNOWN，Saye 2022）

论文没有编号的"定理"，主结果是计算结论。原文：

- 摘要："we verify both conjectures for all $2^n$ with $n \leq 2 \cdot 3^{45} \approx 5.9 \times 10^{21}$."
- 引言："confirm that the ternary representation of 2^n contains every possible ternary digit, for all 16 ≤ n ≤ 2 · 3^45 ≈ 5.9 × 10^21."
- 第 4 节："applied a maximum recursion depth of K = 46. This corresponds to testing the conjectures of Erdős and Sloane
  against all powers 2^n such that n ≤ u_46 = 2 · 3^(46−1) ≈ 5.9 × 10^21. No counterexamples were found."

两个猜想：Erdős（除 2^0, 2^2, 2^8 外 2^n 的三进制含 2）；Sloane（除 2^0,2^1,2^2,2^3,2^4,2^15 外含 0）。
另有说明（未给证明，原文称 "straightforward to show"）：含 1 的版本与 Erdős 版本"essentially equivalent"，例外换成 2^1, 2^3, 2^9。

2·3^45 = 5908625413101667397286（python 计算）。本战役 M2 要求 N > 2·3^45。

注意一个边界细节：Saye 的树到深度 K 时，结点 j < u_K；严格说递归直接检查的是 n < u_46。n = u_46 本身是否单独检查，论文未说（未核实）。
本仓库 CERT 树在 N = u_46 时会包含 r = u_46（见第 3 节），不受此影响。

## 2. 引理与算法（KNOWN，Saye Lemma 3.1 与 Algorithm 1）

记号：a ≡_k b 指 a ≡ b (mod 3^k)；d_k(a) 是 a 的第 k 个三进制位，d_1 是最低位。

**Lemma 3.1**（原文）："For a positive integer k, define u_k := 2 · 3^(k−1). Then
(i) u_k is the smallest positive integer such that 2^(u_k) ≡_k 1;
(ii) if i, j ∈ N and 2^i ≡_k 2^j, then i and j differ by a multiple of u_k;
(iii) if i, j ∈ N, the (k + 1)st ternary digit of 2^(i·u_k + j) is related to that of 2^j via
d_{k+1}(2^(i·u_k+j)) ≡ d_{k+1}(2^j) + i · d_1(2^j) (mod 3)."

附录证明的关键观察 (b)："the last k + 1 ternary digits of 2^(u_k) are (1[0]^(k−1)1)_3"，即 2^(u_k) ≡ 1 + 3^k (mod 3^(k+1))。
因为 d_1(2^j) ∈ {1,2}（2^j 不被 3 整除），(iii) 说明 i = 0,1,2 时第 k+1 位恰好取遍 {0,1,2}：**三个子结点中恰好一个被剪掉**。

**Algorithm 1**（原文 Fig. 1，G_χ(k, u_k, 2^(u_k), j, 2^j)）：
```
1: Determine the first occurrence of digit χ in 2^j.
2: if digit χ not found and j > 16 then
3:     output j (nontrivial counterexample found)
4: if d_k(2^j) = χ then return
6: if k ≥ K then return
8: Compute 2^(u_{k+1}) = (2^(u_k))^3.
9:  Execute G_χ(k+1, 3u_k, 2^(u_{k+1}), j,          2^j)
10: Execute G_χ(k+1, 3u_k, 2^(u_{k+1}), j + u_k,    2^j · 2^(u_k))
11: Execute G_χ(k+1, 3u_k, 2^(u_{k+1}), j + 2u_k,   2^j · (2^(u_k))^2)
```
初值：χ = 2（Erdős）从 G_2(k=1, u=2, 2^u=4, j=0, 2^j=1) 开始；χ = 0（Sloane）从 j=0 与 j=1 两个初值开始。
深度优先，最大深度 K。原文："the total number of powers of two constructed by the recursive algorithm is Θ(2^K), and that every
such power is less than 2^(u_K). On the other hand, the total number of powers of two less than 2^(u_K) is Θ(3^K)."

**可实现的伪代码**（按原文整理；"表 T" 是我的工程建议，不是原文，原文在第 8 行每次调用都做一次立方）：
```
κ = 54                                   # 固定精度：只算 2^j mod 3^κ（原文取值）
T[k]  = 2^(u_k) mod 3^κ, T2[k] = T[k]^2 mod 3^κ   # 预计算 k=1..K（建议）
procedure G(k, j, x):                    # 不变量：x = 2^j mod 3^κ，0 ≤ j < u_k
    p = 最低的 χ 位位置 in x（看 κ 位）
    if p 不存在:                          # 罕见：低 κ 位全无 χ
        对 ℓ = κ+1, κ+2, ...（或成倍增长）用快速幂算 2^j mod 3^ℓ，直到找到 χ 或 ℓ 覆盖 2^j 全部位数
        若全部位数都无 χ 且 j > 16: 输出反例 j
    if digit_k(x) == χ: return           # 剪枝：第 k 位（1 起算）
    if k ≥ K: return
    G(k+1, j,          x)
    G(k+1, j + u_k,    x·T[k]  mod 3^κ)
    G(k+1, j + 2·u_k,  x·T2[k] mod 3^κ)
```
注：需要 κ ≥ K（第 k 位必须在已算精度之内）；K = 47 时 κ = 54 仍足够。

## 3. 与 verify/CERT.md 树的关系（我的推导，未运行任何代码）

CERT 树：第 k 层候选 (k, r)，0 ≤ r < P_k = 2·3^(k−1)，子结点 r + j·P_k（j = 0,1,2）。
P_k 就是 Saye 的 u_k；CERT 的 "trit number k−1 (0-based)" 就是 Saye 的 d_k；CERT 的 D 剪枝就是 Saye 第 4 行（χ = 2）。
所以**同一棵树**，结点集合相同（χ = 2 的情形）：
- CERT 第 1 层有 r=0、r=1 两个候选，r=1（2^1 = 2）立即 D；Saye 只从 j=0 开始。存活结点一致。
- 由 Lemma 3.1(iii)，每个存活结点恰有 2 个存活子结点，所以在没有 N 截断时第 k 层存活数 = 2^(k−1)（KNOWN，由 Saye 引理直接推出）。
  CERT 的 depth_counts[k−1] 在 P_k ≤ N 的各层应当正好是 2^(k−1)。可作为单元测试。
- 差别 1（截断方式）：Saye 用深度 K 截断；CERT 用 r > N 截断（N 类事件）。P_k > N 之后，每个存活结点只剩 j=0 子结点仍 ≤ N
  （j ≥ 1 的都 > N，除个别边界），于是变成一条单链，逐位往高位检查，直到遇到 2（D）或所有位已知（E）。
  这条链等价于 Saye 第 1 行"找 2^j 中第一个 χ"，只是 CERT 每位一层。链长近似几何分布（每层 D 概率约 1/3，HEURISTIC），
  所以 CERT 在截断层以下的 depth_counts 大致按 (2/3)^t 衰减。
- 差别 2：Saye 在**每个**结点（不只叶子）做第 1 行的全数检查；CERT 只在 E 条件下判定例外。覆盖范围相同。
- Saye **没有**用额外的数学剪枝；唯一的剪枝就是第 4 行的第 k 位。"额外"的只是工程上的：固定 54 位精度、罕见时回退到更长精度。
- 对 N = u_46 = 2·3^45：CERT 第 46 层 r < u_46 全 ≤ N；第 47 层 r + u_46 ≤ N 仅当 r = 0（即 n = u_46 被包含）。

**可用的检验数据**（原文数值；与 CERT 的对应是我的推导，未运行）：
- ρ_2(k) := min{n : 2^n ≥ 3^(k−1) 且最后 k 位无 2}。原文："ρ2(100) = 710982592620911336"；
  "ρ2(k) = 201015414581294 for all 82 ≤ k ≤ 98"；"this same example has, in fact, 98 trailing non-2 digits"。
  推论（我的推导）：取 N = 201015414581294，CERT 树应有存活结点 (98, 201015414581294)，且它在第 99 层为 D；
  取 N = 201015414581293 则第 82 层及以下没有存活结点（r = 0 类在 P_k > N 时已终止，k ≈ 30）。
- ρ_0(100) = 388128961376647359（Sloane 方向）。
- 关系 "ρ1(k) = ρ2(k) + 1 for all k"（原文）。

## 4. 算术技巧（KNOWN，原文第 3 节）

- "Except for line 1, all powers of two are computed in the cyclic group modulo 3^κ for a fixed κ."
- "a tailor-made, fixed precision integer type representing a κ = 54 digit ternary number. It is implemented as a three-digit
  number in base 3^18, with each such digit represented by a conventional 32-bit unsigned integer (uint32_t in C++).
  This approach is particularly fast at computing the cubes and multiplications in Algorithm 1."
  （3^18 = 387420489 < 2^32；三进制位提取只需对每个 limb 做 18 次除 3，或查表。）
- 第 1 行罕见情形："it can happen that no such digit occurs in these 54 digits, in which case we switch over to an alternative
  algorithm. The alternative algorithm computes 2^j (via exponentiation-by-squaring) in the cycling group modulo 3^ℓ ...
  in progressively increasing lengths ℓ, until χ is found." "this circumstance never occurred"（指 ℓ 达到全长）。
- 每个子结点只需一次 mod 3^54 乘法；从不做大整数 2^n 的完整计算。
- 并行化：原文只说 "Running on a modest 64-core compute server"，**没有**描述如何分片/并行。具体方式：未核实（原文未写）。
  （CERT.md 的 d0 层分片是本仓库自己的方案，不来自 Saye。）
- 工程建议（我的，非原文）：3^40 < 2^64，3^80 < 2^128，可用 64 位 limb 或 __int128 + Montgomery/Barrett；预计算 T[k]、T2[k] 以去掉第 8 行重复立方；
  深度优先递归的末几层可展开或批量 SIMD。

## 5. 算力与成本缩放

- 原文："Running on a modest 64-core compute server for a few days"，K = 46。硬件型号、CPU 小时数、每结点耗时：原文均未给出（未核实）。
- 两个猜想（χ = 2 与 χ = 0）都跑了；是否同一次运行、各自占比：未写（未核实）。
- 缩放（KNOWN，原文 Θ(2^K)）：结点数 Θ(2^K)，界 N = u_K = 2·3^(K−1)，所以成本 ∝ N^(log_3 2) ≈ N^0.631；
  界乘 3（K 加 1）成本翻倍；一半结点在最深一层。

**我的估计（ESTIMATE，非原文）**：
- χ = 2 树到深度 46：Σ 2^(k−1) ≈ 2^46 ≈ 7.0×10^13 结点；χ = 0 有两个初值，约 2^47。合计约 2.1×10^14 结点。
- "a few days" 取 2–5 天 × 64 核 = 1.1×10^7–2.8×10^7 核秒，折合约 52–131 ns/结点/核（取 3 天约 79 ns）。
- 推到 N = 2·3^46（K = 47，只做 Erdős χ = 2）：约 2^47 ≈ 1.4×10^14 结点，按上面单核速度，4 核约 **21–53 天**（3 天假设下约 32 天）。
  若实现做到 ~10–20 ns/结点（预计算表、64 位 limb、无递归开销；纯猜测，未测），4 核约 4–8 天。
  这些数字依赖对 "a few days" 的解读与本容器 CPU，未经任何基准测试。
