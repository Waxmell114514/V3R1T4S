所有数字来自 reports/T0_phase0.log、reports/calib_*.json 和本会话的命令输出。

## 已知事实复现
- verify/brute.py：n ≤ 20000 中 2^n 三进制无数字 2 的 n 恰为 [0, 2, 8]。
- 恰 2 子节点引理：k ≤ 40 逐层数值成立（2^(P_k) ≡ 1 + c·3^k mod 3^(k+1)，3 ∤ c）。
- verify/tree_py.py（纯 Python）与 verify/tree_ref.c（C，base-3^40 多肢算术）对 N ∈ {10^3, 10^5, 2·3^12}、
  分片 m ∈ {1, 3} 输出逐项一致；树的每层存活数与"直接按定义枚举"一致（N ∈ {300, 3000, 10^4}）。
- 篡改一个分片的计数、删除一个分片：check_cert.py 均判 FAIL；诚实证书集判 PASS。

## 校准中发现并修正的错误（记录在案）
第一版规则在例外节点（如 r = 0）处省略 j = 0 子类，这会漏掉 n = 6、12 等同余类成员。
"按定义枚举"的测试在 N = 3000 上判 FAIL 抓到了它。修正后的规则：例外 r 只在其类与 [0, N] 的交只剩 r 时
才终止并报告 E（verify/CERT.md 第 3 条）。三处实现同步修正后全部通过。
这说明 T0 的"按定义枚举"测试是有效的，后续不得删减。

g0 与参考实现在 N = 2·3^20 上计数、例外、事件数、leaf_digest 全部一致：**M1 的复现条件已满足**。
观察：N = 2·3^K 时事件数约 2^(K+3)。外推 Saye 纪录 2·3^45 约 2.8e14 事件，2·3^46 约 5.6e14 事件。
参考实现约 6e6 事件/秒：单独复算整段纪录约 1.5 CPU 年，因此长跑只抽查分片（recheck_fraction 0.0005，至少 5 片）。
要在本机 4 核数天内推过纪录，搜索引擎需达到约 1e9 事件/秒（全核），即比 g0 快约 5000 倍。这是计算轨道的首要瓶颈。
